## Не входило в проверку 31.07.2026

- запуск версии в Yandex Cloud Functions;
- промышленный триггер Object Storage;
- реальная загрузка вложений и доставка сообщений в MAX;
- фактическое время выполнения функции при большом числе паллетов;
- повторная доставка одного и того же события Object Storage.

Эти пункты нельзя считать подтверждёнными локальными тестами.

## Исторический план перед включением промышленного триггера

Триггер уже включён; для следующих выпусков применять [RELEASE.md](RELEASE.md).
Публикация при маршруте на `$latest` сразу меняет рабочую версию, поэтому
сначала требуется закрепить действующий выпуск через `production-stable`.

1. Проверить diff и принять PR.
2. Создать новую версию функции без переключения промышленного трафика.
3. Сверить переменные `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `S3_ENDPOINT`,
   `EQUIPMENT_TASKS_BUCKET` и `EQUIPMENT_TASKS_PREFIX`.
4. Убедиться, что роль функции читает и `equipment-reports/`, и
   `equipment-tasks/`.
5. Проверить установленный timeout с учётом последовательной отправки одного
   сообщения на каждый паллет.
6. Выполнить контролируемый ручной вызов новой версии сначала с v1, затем с
   v2 на два паллета.
7. Для v2 проверить сканером каждый полученный ярлык и сверить SSCC,
   оператора, число коробов и число штук.
8. Только после этого переключить промышленный триггер на новую версию.
9. Сохранить возможность немедленно вернуть предыдущую версию функции.

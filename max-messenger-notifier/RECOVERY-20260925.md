# MAX upload incident — 25 September 2026

`fu.oneme.ru` returned HTTP 200 with `code=upload.error` for both multipart
fields (`file`, `data`) and both MAX API domains. No message was sent by those
attempts. The image endpoint `iu.oneme.ru` successfully returned an image token.

Report PNGs now use `type=image` with the documented `photos.*.token` response.
The PNG generation/SSCC data and production processing are unchanged.

An additional `index.task_handler` entrypoint is a notification-only temporary
replacement for the legacy task bot. The owner approved messages containing
24-hour presigned links while MAX file upload is unavailable. The route is
strictly restricted to the existing equipment-task bucket/prefix, only reads
S3, checks the JSON identity, sends one text message, and returns its MAX ID.
It does not write tags, put/delete objects, enqueue messages or invoke workers.
Timeouts/unknown send results must be reconciled before a manual replay.

Task links use HTML formatting: a bold heading, escaped task ID, and an
escaped anchor labelled `📄 Скачать JSON`. The URL still expires after 24 hours,
but is hidden behind the label. The obsolete upload-outage warning is omitted;
`disable_link_preview=true` prevents an additional URL preview. This display
was confirmed in the user-approved test chat before production rollout.
Only new notifications use the updated format; existing messages and production
inputs are not replayed. The report/image route is unchanged.

Both routes use `platform-api2.max.ru`. `russian-root.pem` was downloaded over
verified HTTPS from the official source:

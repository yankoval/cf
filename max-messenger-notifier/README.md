# MAX messenger notifier

Yandex Cloud Function получает событие загрузки отчёта оборудования из
Object Storage и отправляет обратную связь в MAX.

## Поддерживаемые отчёты

### v1

Короба читаются из корневого `readyBox`. Функция ищет соответствующее задание
`equipment-tasks/<report-id>.json`:

- если новое задание содержит `reportSchemaVersion: 1` и ровно один SSCC в
  `palletNumbers`, весь отчёт считается одним паллетом; функция отправляет
  только паллетный ярлык с назначенным SSCC и параметрами отчёта;
- если исторического задания нет или в нём отсутствует `palletNumbers`,
  сохраняется прежнее поведение: только сводка и информационная PNG-карточка.

Несовпадение ID, версии задания, некорректный SSCC или несколько паллетных
SSCC в задании v1 считается ошибкой, и уведомление по такому отчёту не
отправляется.

### v2

Короба читаются из всех `readyPallet[].readyBox[]`. Функция:

1. проверяет `schemaVersion: 2`, закрытие паллетов и коробов, а также
   контрольные цифры SSCC;
2. загружает `equipment-tasks/<report-id>.json`;
3. сверяет ID имени файла, отчёта и задания и проверяет, что каждый SSCC
   паллета заранее назначен в `task.palletNumbers`;
4. отправляет отдельный печатный PNG-ярлык для каждого паллета без
   дополнительной общей сводки.

Сообщение с ярлыком содержит полный SSCC паллета, оператора, количество
коробов и штук, а также компактный перечень номеров коробов именно этого
паллета. Печатный PNG содержит штрихкод GS1-128 с AI `00`. Для генерации
используется `python-barcode` и уже включённый в функцию Pillow.

Страховые SSCC, назначенные заданию, но не использованные в отчёте, в MAX не
отправляются.

## Переменные окружения

| Переменная | Обязательная | Значение |
|---|---:|---|
| `MAX_BOT_TOKEN` | да | Токен бота MAX. |
| `MAX_CHAT_ID` | да | Чат для уведомлений. |
| `AWS_ACCESS_KEY_ID` | да | Ключ Object Storage. |
| `AWS_SECRET_ACCESS_KEY` | да | Секрет Object Storage. |
| `S3_ENDPOINT` | нет | По умолчанию `https://storage.yandexcloud.net`. |
| `EQUIPMENT_TASKS_BUCKET` | нет | Бакет заданий. По умолчанию используется бакет отчёта. |
| `EQUIPMENT_TASKS_PREFIX` | нет | По умолчанию `equipment-tasks`. |

Роль функции должна иметь право чтения как отчёта, вызвавшего событие, так и
соответствующего задания оборудования.

## Формат уведомлений

Для отчёта v1 по новому заданию отправляется одно сообщение:

- ярлык единственного паллета со всеми параметрами, коробами и товарами
  отчёта.

Для отчёта v2 с двумя паллетами отправляются два сообщения:

1. ярлык паллета 1/2;
2. ярлык паллета 2/2.

Исторический v1 без назначенного паллетного SSCC по-прежнему получает одну
старую сводку, поскольку сформировать достоверную паллетную этикетку для него
невозможно.

Повторный результат контрольного сканирования не хранится этой функцией.
Сканирование должно обрабатываться отдельной принимающей процедурой, которая
сравнивает код с заданием и отчётом и сохраняет идемпотентное состояние
подтверждения.
